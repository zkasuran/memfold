# Daemon REST

`@memfold/daemon` (FSL-1.1-ALv2) puts a small HTTP API in front of a memfold store and mirrors every
write to an append-only op-log that git can sync. The SQLite database is a rebuildable projection of
that log. The normative contract is [`../spec/rest.md`](../spec/rest.md); this page is the working
reference.

## Run it

```sh
memfold-daemon
```

Configuration is read from the environment:

| Variable | Default | Purpose |
|---|---|---|
| `MEMFOLD_DB` | `memfold.db` | SQLite file path. `:memory:` for an ephemeral store. |
| `MEMFOLD_OPLOG` | `<MEMFOLD_DB>.oplog.jsonl` | Append-only op-log path (the git-syncable source of truth). |
| `MEMFOLD_PORT` | `7077` | Port to listen on. |
| `MEMFOLD_HOST` | `127.0.0.1` | Bind address. Loopback by default. |
| `MEMFOLD_TOKEN` | unset | When set, every route except `GET /health` needs `Authorization: Bearer <token>`. |

## Security posture

The daemon binds to `127.0.0.1` and is **unauthenticated unless `MEMFOLD_TOKEN` is set**. Without a
token, anyone who can reach the port has full read and write access to the store. The startup log line
states which mode it is in. Set `MEMFOLD_TOKEN` before you bind to a non-loopback host or expose the
port, and terminate TLS in front of it, because the bearer token is sent in clear text otherwise.

```sh
MEMFOLD_TOKEN=$(openssl rand -hex 16) MEMFOLD_DB=./.memory/index.db memfold-daemon
```

## API

| Method | Path | Body or query | Result |
|---|---|---|---|
| GET | `/health` | | `{ status, vectorEnabled, count }` |
| POST | `/memories` | a new-record input | `201` and the created record |
| GET | `/memories` | `?scope=&scopePath=&type=&status=` | an array of records |
| GET | `/memories/:id` | | the record, or `404` |
| PATCH | `/memories/:id` | a partial patch | `200` and the new record version |
| DELETE | `/memories/:id` | | `204` (tombstone) |
| POST | `/search` | `{ query, limit?, scope?, scopePath?, types? }` | an array of search hits |

Request bodies are validated with zod. A bad body returns `400` with the issues. A tombstoned record
reads as `404` from `GET`, `PATCH` and `DELETE`. `PATCH` writes a new record version rather than
mutating in place, so history is preserved.

## Examples

Create a record:

```sh
curl -s localhost:7077/memories \
  -H "authorization: Bearer $MEMFOLD_TOKEN" \
  -H 'content-type: application/json' \
  -d '{
    "type": "convention",
    "scope": "dir",
    "scope_path": "packages/api",
    "body": "API errors return { error: { code, message } }; never leak stack traces.",
    "summary": "API errors return { error: { code, message } }.",
    "tags": ["api", "errors"],
    "dedup_key": "conv:api-error-shape",
    "provenance": { "source": "user" }
  }'
```

Required on create: `type`, `scope`, `body` and `provenance`. The daemon assigns `id`, `rev`,
`content_hash`, `hlc` and the timestamps.

Search:

```sh
curl -s localhost:7077/search \
  -H "authorization: Bearer $MEMFOLD_TOKEN" \
  -H 'content-type: application/json' \
  -d '{ "query": "how do handlers return errors", "limit": 5 }'
```

Update, then forget:

```sh
curl -s -X PATCH localhost:7077/memories/$ID \
  -H "authorization: Bearer $MEMFOLD_TOKEN" \
  -H 'content-type: application/json' \
  -d '{ "salience": 0.9 }'

curl -s -X DELETE localhost:7077/memories/$ID -H "authorization: Bearer $MEMFOLD_TOKEN"
```

## The op-log

Every `POST`, `PATCH` and `DELETE` appends one line to the op-log: `{ kind, record?, id?, hlc, at }`,
flushed with an fsync so a crash cannot leave a half-written record. The log is plain append-only
JSONL, so git merges union new lines rather than conflict, and the SQLite cache can be regenerated by
replaying the log in write order.

## Embed it in a process

```ts
import { createApp, OpLog } from '@memfold/daemon'
import { SqliteStore, makeHlcState, newNodeId } from '@memfold/core'

const store = new SqliteStore('memfold.db')
const app = createApp(store, {
  hlc: makeHlcState(newNodeId()),
  oplog: new OpLog('memfold.db.oplog.jsonl'),
  token: process.env.MEMFOLD_TOKEN,
})

// app.fetch is a standard Fetch handler; serve it with @hono/node-server,
// or call app.request(...) directly in tests.
```
