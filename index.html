Universal memory for AI coding tools

One memory for every AI coding tool and agent framework

Write a rule or a fact once. memfold keeps it in a single versioned, local-first store, then compiles it into every tool's native file, serves it live over MCP and syncs it through a local daemon.

The problem

Rules and memory are scattered across a moving target of file formats

One 2026 survey counted 21 instruction-file paths across 18 tool families, and only 7 of the 18 publish any rule for which file wins when several apply. The pain that grows out of that is documented, not anecdotal.

Duplication and drift

The same facts get copied into CLAUDE.md, AGENTS.md and .cursor/rules. A June 2026 study measured stale code references in 23% of a 356-repo sample and named it context rot.

Secrets leak in

Rules files are meant to be committed, so they are the wrong place for a credential. A population-scale scan found over 1,230 hardcoded keys and tokens across AI instruction files in public repos.

Memory does not follow you

Memory is siloed by design. Switch tools or machines and the agent starts blank, with no versioning, no provenance and no merge story for conflicting rules.

How it works

One record, a defined winner, three ways out

The canonical unit is the Memory Record: a typed, scoped item stored as YAML frontmatter plus a markdown body in a git-diffable directory. A resolver applies explicit precedence, so the winning layer is known instead of arbitrary.

Scoped and merged

Four scopes from global to session, most specific wins. A hybrid logical clock drives deterministic last-writer-wins merge across machines with no central lock.

Ranked and versioned

Hybrid retrieval fuses keyword and vector search. Salience and decay rank results. Deletes are tombstones, so every memory has a git-style history and a rollback.

Secret-gated

Every write runs a pre-write secret scan and refuses to persist a detected credential. The compiler runs the scan again before it touches a file a tool will commit.

Surface 1 of 3

Compile the store out to every tool's native file

memfold ships 8 adapters and writes each tool's real files. Files a human also edits get a fenced managed block, so hand-written prose survives every recompile.

// detect the tools this repo uses, then write their files
import { detectInstalled, compileAll, writeCompiled } from '@memfold/adapters'

const adapters = await detectInstalled(root)
const files = compileAll(records, adapters, root)
await writeCompiled(files) // merges blocks, blocks secrets
Targets
  • Claude Code (CLAUDE.md, .claude/rules)

  • Cursor (.cursor/rules/*.mdc), Windsurf
  • Copilot (.github/copilot-instructions.md)
  • Cline (.clinerules), Aider (CONVENTIONS.md)
Surface 2 of 3

Serve the same memory live over MCP

Every read and write is a tool, the one primitive every MCP client implements, so tool-only clients keep the full surface. Point any client at the memfold-mcp binary.

// MCP client config
{
  "mcpServers": {
    "memfold": {
      "command": "memfold-mcp",
      "env": { "MEMFOLD_DB": "./.memory/index.db" }
    }
  }
}
Tools
  • memory_search — ranked hybrid search
  • memory_write — store a record, gated
  • memory_get — fetch one record
  • memory_list — browse and audit
  • memory_forget — tombstone a record
Surface 3 of 3

Sync through a local daemon, or embed the SDK

A local REST daemon fronts the store and mirrors every write to a git-syncable append-only op-log. The TypeScript SDK gives the same surface embedded or remote, so you can start in-process and move to the daemon without changing call sites.

// embedded, in-process
import { Memfold } from '@memfold/sdk'

const mem = new Memfold('./.memory/index.db')
await mem.add({ type: 'fact', scope: 'project',
  body: 'The build runs on Node 22' })
const hits = await mem.search('node version')
Also in the SDK
  • MemfoldClient — the same API over the daemon
  • LangGraph BaseStore adapter
  • Vercel AI SDK chat-message store
  • Loopback bind, bearer-token auth on the daemon
For developers

Packages and licensing

memfold is source-available, licensed by component. The spec and the client packages are Apache-2.0, so anyone can implement the protocol and interoperate. It is not OSI "open source".
