# @memfold/daemon

A local-first HTTP daemon for memfold. It puts a small REST API in front of a `MemoryStore` from `@memfold/core` and mirrors every write to an append-only op-log that git can sync. The SQLite database is a rebuildable projection of that log.

## Running

```bash
memfold-daemon
```

Configuration is read from the environment:

| Variable | Default | Purpose |
|---|---|---|
| `MEMFOLD_DB` | `memfold.db` | SQLite file path. Use `:memory:` for an ephemeral store. |
| `MEMFOLD_OPLOG` | `<MEMFOLD_DB>.oplog.jsonl` | Append-only JSONL op-log path (the git-syncable source of truth). |
| `MEMFOLD_PORT` | `7077` | Port to listen on. |
| `MEMFOLD_HOST` | `127.0.0.1` | Bind address. Loopback by default. |
| `MEMFOLD_TOKEN` | unset | When set, every route except `GET /health` requires `Authorization: Bearer <token>`. |

## Security posture

The daemon binds to `127.0.0.1` by default and is **unauthenticated unless `MEMFOLD_TOKEN` is set**. Without a token, anyone who can reach the port has full read and write access to the store. The startup log line states which mode it is in. Set `MEMFOLD_TOKEN` before binding to a non-loopback host or exposing the port, and terminate TLS in front of it (the bearer token is sent in clear text otherwise).

## API

| Method | Path | Body / query | Result |
|---|---|---|---|
| GET | `/health` | — | `{ status, vectorEnabled, count }` |
| POST | `/memories` | `NewRecordInput` | `201` + the created `MemoryRecord` |
| GET | `/memories` | `?scope=&scopePath=&type=&status=` | `MemoryRecord[]` |
| GET | `/memories/:id` | — | the `MemoryRecord`, or `404` |
| PATCH | `/memories/:id` | partial patch | `200` + the new record version |
| DELETE | `/memories/:id` | — | `204` (tombstone) |
| POST | `/search` | `{ query, limit?, scope?, scopePath?, types? }` | `SearchHit[]` |

Request bodies are validated with zod; a bad body returns `400` with the zod issues. A tombstoned record reads as `404` from `GET`/`PATCH`/`DELETE`. `PATCH` writes a new record version through `reviseRecord` rather than mutating in place, so history is preserved.

## Embedding in another process

```ts
import { createApp, OpLog } from '@memfold/daemon'
import { SqliteStore, makeHlcState, newNodeId } from '@memfold/core'

const store = new SqliteStore('memfold.db')
const app = createApp(store, {
  hlc: makeHlcState(newNodeId()),
  oplog: new OpLog('memfold.db.oplog.jsonl'),
  token: process.env.MEMFOLD_TOKEN,
})

// app.fetch is a standard Fetch handler; serve it with @hono/node-server, or
// call app.request(...) directly in tests.
```

## The op-log

`OpLog` is an append-only JSONL writer. Each line is one op, `{ kind: 'upsert' | 'tombstone', record?, id?, hlc, at }`, flushed with an fsync so a crash cannot leave a half-written record. `oplog.all()` replays the file in write order. Because it is plain text and append-only, it merges cleanly under git and lets a rebuilt SQLite cache be regenerated by replaying the log.
